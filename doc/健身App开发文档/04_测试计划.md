## 范围与策略

一期覆盖家庭目录、计划、训练生命周期、历史和备份；二期追加器械目录、动作替换、单位转换、趋势及升级回归。全部动作图片和 GIF 从首期 APK 本地提供，测试以数据不丢失、主流程可持续使用、飞行模式媒体可用和资源完整性为重点，不验证健身疗效。不测试未开发的账号/AI/支付功能。

## 环境与数据

- 开工记录实际 JDK、Gradle、AGP、Kotlin、SDK、Room 版本；不凭本文件假设兼容。
- 单元测试使用固定时钟与测试数据；Room、迁移、事务在设备/模拟器执行。
- 一期验收覆盖 minSdk 对应系统和较新系统；较新版本按开工时可用稳定环境记录。
- 使用测试 UUID、虚构计划与成绩，不导入真实个人敏感数据。
- 准备正常目录、重复ID、缺失中文、需额外设备、已移除动作、各版本数据库及损坏备份。
- 网络：飞行模式、正常网络；生命周期：后台、旋转、强制停止、重启；文件：取消、错误文件、模拟无空间。
- 媒体：准备完整本地资源包、缺失文件、错误路径、损坏图片、损坏 GIF、动作 ID 错配、无远程 URL 构建；记录图片/GIF实际数量、总大小、APK 体积、缩略图加载耗时、详情 GIF 首帧耗时和内存观测值。
- 授权：记录 Gym visual 本地复制及 APK 分发授权状态、署名、凭证位置、核验人和日期；未执行或未确认只记录为未执行/阻塞。

## 进入条件

任务实现可构建；用例及测试数据就绪；目标数据版本可追溯；设备/模拟器可用。缺环境时记录阻塞，不把未执行项计作通过。

## 执行命令

```bash
./gradlew :app:assembleDebug :app:lintDebug
./gradlew :app:testDebugUnitTest
./gradlew :app:connectedDebugAndroidTest
```

资源校验命令由工程实现提供，例如 `./gradlew :app:verifyMediaResources`；命令必须输出可保存的资源校验报告，不能以文件数量估算替代逐文件校验。

命令适用于建议的 app 模块；实际工程不同须更新命令并保留真实输出。TDD 先记录业务断言预期失败，再实现、验证通过；环境错误不是预期红灯。
