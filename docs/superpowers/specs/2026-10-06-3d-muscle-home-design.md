# 健身 App 3D 肌肉探索首页设计规格

日期：2026-10-06
状态：待用户批准；本文是设计规格，不代表已实现或已验收。
适用工程：`com.don.homefitness` 个人离线 Android App

## 1. 目标与边界

打开 App 后默认进入 3D 人体探索首页。用户通过点击肌肉群查找动作，再进入现有本地动作详情或加入训练计划；原动作库保留为次级入口。

本次设计包含：

- 成年男性和成年女性两套标准、自然比例、健身教学风格模型。
- 男性不透明运动内裤；女性不透明运动内衣和内裤。
- 3D 旋转、缩放、恢复默认视角和前/侧/后观察。
- 肌肉区域高亮、中文名称、主要/辅助训练动作分组。
- 肌肉区域到动作目录的显式 ID 映射。
- 全部模型、材质、映射和辅助资源本地打包，飞行模式可用。
- 后台暂停渲染，离开页面释放渲染资源，返回时恢复视角和选择状态。
- 模型加载失败时的肌肉文字列表兜底。

本次不包含：AR、联网下载、账号同步、AI 识别、训练处方、热量或体能推断，以及用二维图片模拟三维旋转。

## 2. 当前工程基线

当前工程使用 Kotlin、Jetpack Compose、Navigation、ViewModel、StateFlow、Room 和 Coil；首页入口仍是 `CatalogScreen`，未接入 3D 引擎，也没有人体模型或肌肉区域资源。现有动作图片/GIF 已采用 APK 本地资源和动作 ID 映射，必须继续复用，不能改回远程加载。

当前 `minSdk=26`、`compileSdk=37`、Java 17。3D 方案必须在 API 26 上有明确降级路径，并在较新 API 设备上验证渲染效果。

## 3. 技术选型

### 3.1 推荐方案：SceneView + Filament + glTF/GLB

Google Filament 是实时 PBR 渲染引擎，提供 Android 渲染和 glTF 2.0 加载能力。SceneView 在 Compose 中提供 Filament 场景、模型节点和相机/手势封装。推荐先以 SceneView 作为 Compose 集成层；若区域命中、生命周期或版本稳定性不足，再下沉到直接 Filament API。

优点：

- 满足真正 3D 渲染要求，不依赖二维帧切换。
- glTF/GLB 适合作为本地 APK 资源格式。
- 可保留每个肌肉区域的独立 mesh、材质和节点 ID。
- 与现有 Compose 页面集成成本低于引入完整游戏引擎。

代价和风险：

- SceneView 是第三方 Compose 封装，需要锁定版本并审查许可证、传递依赖和 API 稳定性。
- Filament 原生库会增加 APK 体积，需要按 ABI 和压缩后的实际结果记录。
- 低端 GPU 的帧率、纹理内存和首次加载时间必须实测，不能用理论值验收。

### 3.2 备选方案

| 方案 | 结论 | 原因 |
| --- | --- | --- |
| 直接 Filament | 作为降级方案 | 控制力强，但相机、命中测试、生命周期和 Compose 互操作代码更多 |
| Unity/Godot 嵌入 | 不推荐 | 包体、启动耗时、Android 集成和维护成本过高 |
| 自绘 Canvas/二维图片 | 排除 | 不满足真正 3D 模型和任意角度查看 |

在编写产品依赖前必须完成一个最小 Spike：加载一个本地 GLB、旋转/缩放、点击节点、暂停/恢复渲染，并输出 APK 增量和设备性能数据。

## 4. 资源与许可门槛

### 4.1 模型资源要求

男性和女性模型各自至少包含：

- 身体基础网格。
- 可独立命中的肌肉区域 mesh 或不可见点击代理 mesh。
- 身体材质和服装材质。
- 默认相机目标、初始距离和模型单位信息。
- 区域 ID 元数据或可稳定映射的节点名。

如果第三方模型只有一个整体网格，不能仅凭节点名称声称支持肌肉点击。必须选择以下方案之一并记录工具和产物：

1. 在建模工具中按肌肉区域拆分 mesh；
2. 增加与模型表面对应的独立透明点击代理网格；
3. 由渲染层维护区域射线和三角形索引映射。

若上述方案无法保证正面、侧面和背面命中准确，则保留文字肌肉列表并阻塞 3D 肌肉点击验收。

### 4.2 本地资源目录

建议目录：

```text
app/src/main/assets/body/
  male/body.glb
  female/body.glb
  male/textures/*
  female/textures/*
  muscle-regions.json
  muscle-action-map.json
  model-manifest.json
  model-check-report.json
  NOTICE.md
```

`model-manifest.json` 至少记录模型 ID、文件路径、SHA-256、字节数、网格数、材质数、区域数、来源仓库、来源 commit、许可证和署名。

`model-check-report.json` 记录文件缺失、GLB/glTF 解析失败、纹理缺失、未映射区域、重复区域 ID、远程引用、模型总大小和 APK 增量。任一未处理错误都阻塞验收。

### 4.3 许可证

人体模型、服装、材质、纹理、SceneView、Filament 和转换工具分别记录许可证。开源许可证允许使用不等于自动允许随个人 APK 分发；模型资源必须有独立的本地复制和 APK 分发状态。

未取得模型资源分发许可时，只能做不含第三方模型的渲染 Spike，不能将模型放入正式 APK，也不能将验收标记为通过。

## 5. 数据模型与映射

### 5.1 肌肉群固定 ID

一期固定以下逻辑 ID，男女模型共用：

```text
chest
shoulders
back
biceps
triceps
forearms
abs
glutes
quadriceps
hamstrings
calves
```

后续可扩展，但不得修改已有 ID 的语义。中文名称由 `muscle-regions.json` 提供，不从英文名称运行时模糊推断。

### 5.2 区域到动作映射

```json
{
  "regionId": "chest.left",
  "muscleGroupId": "chest",
  "displayNameZh": "胸部",
  "meshNodeIds": ["male.chest.left", "female.chest.left"],
  "primaryExerciseIds": ["0001", "0042"],
  "secondaryExerciseIds": ["0100"]
}
```

动作归类规则：

- `primaryExerciseIds` 是人工审核的主要训练动作白名单，优先展示。
- `secondaryExerciseIds` 来自动作的 `secondary_muscles` 显式审核映射，只作为辅助参与动作。
- 一期继续使用家庭设备白名单，只展示徒手和哑铃动作。
- 二期开放健身房场景后，复用同一 `exerciseId` 和本地媒体，不新建重复动作。
- 映射中不存在的动作 ID、动作库中不存在的 ID 或 target 不一致都必须由校验器报告。

### 5.3 交互状态

`MuscleExplorerUiState` 保存：

- `modelGender`：`MALE` / `FEMALE`；
- `selectedMuscleGroupId`：可空；
- `cameraOrbit`：水平角、垂直角、距离；
- `isModelReady`、`modelError`；
- `gestureMode`：`IDLE` / `ROTATING` / `PINCHING`；
- `exercisePanelExpanded`；
- 当前场景 `HOME` / `GYM`。

切换男女模型只更换模型资源和节点映射，不清空肌肉筛选、场景、设备条件或动作搜索条件。模型切换时保留逻辑 `muscleGroupId`，重新解析到对应性别的 mesh 节点。

## 6. 首页交互设计

### 6.1 页面结构

```text
顶部：性别切换｜恢复视角｜动作库
中部：3D 人体视口
       └─ 模型加载/失败状态
底部：已选肌肉名称
       主要训练动作横向/纵向列表
       辅助参与动作列表
       小区域文字肌肉列表入口
```

### 6.2 手势规则

- 单指拖动：旋转模型；不触发肌肉选择。
- 单击且位移低于点击阈值：执行命中测试并选择肌肉。
- 双指缩放：调整相机距离，限制最小和最大距离。
- “恢复视角”：回到性别对应的默认角度和距离，但保留当前肌肉选择。
- 正面、侧面和背面均由实际射线命中选择；不得仅为正面提供交互。
- 难以点击的前臂、小腿等区域，在文字列表中始终可选。

建议初始手势阈值和相机范围只作为默认值，最终以设备人工测试调整；未测量前不得写入验收报告。

### 6.3 动作面板

点击肌肉区域后：

1. 高亮对应区域并显示中文名称；
2. 展开动作面板；
3. 先显示主要训练动作；
4. 再显示辅助参与动作并明确标签；
5. 点击动作进入现有本地详情页；
6. 详情页继续使用本地图片、GIF、中文步骤和加入计划入口。

空结果时显示“暂无符合当前家庭设备条件的动作”，并提供打开动作库、清除筛选和查看文字肌肉列表入口。

## 7. 渲染与生命周期架构

新增职责建议：

```text
feature/muscle/
  MuscleExplorerScreen.kt
  MuscleExplorerViewModel.kt
  MuscleExplorerUiState.kt
  MuscleRegionRepository.kt
  MuscleActionMapper.kt
  MuscleModelRenderer.kt
  MuscleModelLifecycle.kt
data/body/
  BodyModelManifest.kt
  BodyModelValidator.kt
```

`MuscleModelRenderer` 只负责场景、相机、节点命中和高亮；`MuscleActionMapper` 只负责固定 ID 映射；`MuscleExplorerViewModel` 只负责状态和现有 CatalogRepository 查询。渲染引擎对象不能泄漏到 Room、Repository 或测试域。

生命周期：

- `ON_START`：创建或恢复渲染资源；
- `ON_RESUME`：恢复渲染循环和触摸输入；
- `ON_PAUSE`：停止渲染循环，释放临时帧资源，保留逻辑状态；
- `ON_STOP`：销毁场景节点、纹理和引擎引用；
- 返回页面：重新加载模型，恢复性别、相机和选择状态。

页面离开和后台切换必须有日志或测试钩子证明渲染器已停止；不能依靠 Compose 组合树偶然销毁。

## 8. 兼容性、性能与包体评估

评估只接受真实测量：

- API 26 基线设备：能否加载、旋转、命中和恢复。
- 较新 API 设备：帧率、首次加载、内存、后台释放。
- 低性能设备：连续旋转时卡顿、触摸丢失和模型降级。
- APK：3D 引擎 native 库、两个模型、纹理压缩和总包体增量。

优化顺序：

1. 使用 GLB 和压缩纹理；
2. 控制三角形、材质和纹理分辨率；
3. 仅保留当前性别的 GPU 资源，另一性别切换时按需加载；
4. 限制后台渲染；
5. 低端设备使用简化材质/低细节模型，但不切换为二维图片；
6. 只有测得加载失败时才提供文字入口。

首次 Spike 必须输出：模型文件大小、压缩后 APK 增量、冷加载时间、稳定帧率样本、模型页 PSS、旋转期间 PSS、后台 PSS 和设备型号。目标值可以在 Spike 后确定，不能预先伪造为验收结果。

## 9. 错误处理

| 错误 | 用户行为 | 验收要求 |
| --- | --- | --- |
| 模型文件缺失/损坏 | 显示文字肌肉列表和动作库入口 | 不影响原动作库和计划 |
| 区域未映射 | 显示“该区域暂未关联动作” | 报告列出未映射 ID |
| GPU/渲染初始化失败 | 显示文字入口 | 不崩溃，不循环重试 |
| 动作媒体缺失 | 沿用现有详情错误状态 | 不回退远程 URL |
| 后台/页面离开 | 停止渲染并释放资源 | 日志或测试可证明释放 |

## 10. 分迭代实施计划

### I7-T01 3D 模型资产与渲染 Spike

- 固定男女模型来源、许可证、署名和 APK 分发授权状态。
- 检查模型是否有独立肌肉 mesh；若没有，完成拆网格或点击代理方案评估。
- 引入候选 SceneView/Filament 依赖前先锁版本并记录兼容性。
- 加载本地 GLB，完成旋转、缩放、默认视角、节点点击和前/侧/背面验证。
- 输出模型校验报告、包体增量、加载时间、帧率、PSS 和后台释放数据。
- 未取得合法模型授权或无法稳定命中区域时，I7 不得验收通过。

### I7-T02 首页人体探索与肌肉状态

- 新增人体探索首页和性别切换。
- 实现逻辑肌肉 ID、中文名称、高亮和文字列表兜底。
- 实现手势区分，确保旋转拖动不误触选择。
- 保留当前场景、设备过滤、肌肉选择和视角状态。

### I7-T03 显式肌肉动作映射

- 新增 `muscle-regions.json` 和 `muscle-action-map.json`。
- 校验 region ID、mesh ID、muscle group ID、动作 ID、target 和 secondary_muscles。
- 接入家庭徒手/哑铃过滤和主要/辅助动作排序。
- 复用原动作详情、本地 GIF/图片和加入计划流程。

### I7-T04 离线、生命周期与发布验收

- 飞行模式首次启动和无网络完整使用。
- 模型加载失败、映射缺失、资源损坏和动作媒体异常。
- 页面离开、后台、返回、旋转和进程重建。
- API 26、较新 API、低性能设备和 AndroidTest。
- 完成许可证、包体、内存、帧率和资源校验报告。

## 11. 测试与验收

必须新增或扩展以下测试：

- 男女模型切换不清除当前肌肉/场景/设备筛选。
- 正面、背面和侧面节点命中映射到正确 muscle group ID。
- 旋转拖动不触发选择；点击触发选择；缩放不改变选择。
- muscle group ID 到 primary/secondary exercise ID 的映射正确。
- 一期只显示家庭徒手、哑铃动作，二期场景才显示器械动作。
- 首次启动和飞行模式下加载本地模型和动作媒体。
- 页面离开、后台切换停止渲染并释放资源，返回恢复视角和选择。
- 模型/材质/映射损坏时文字入口可用且不崩溃。
- 低性能设备上的帧率、触摸响应、内存和加载时间均以实测报告为准。

最终验收必须同时具备：代码测试、设备测试、资源校验报告、模型授权记录、包体/性能报告和交付 commit。未执行项目保持“未执行”，外部授权未确认时保持“阻塞”。

## 12. 设计决策待批准项

请在开始写实施计划前确认：

1. 接受 SceneView + Filament + 本地 GLB/glTF 作为首选技术路线，并允许在 Spike 失败时下沉到直接 Filament。
2. 接受“模型没有独立肌肉网格时必须拆网格或增加点击代理，不能用名称模糊匹配”的门槛。
3. 接受模型许可证和 APK 分发授权未确认前不导入正式 APK、不通过验收。
4. 接受先完成 I7-T01 Spike，再进行首页和动作映射实现。
